# จองอะไหล่ตอนอนุมัติราคาและไม่ยอมให้สต็อกติดลบ

การตัดสต็อกตอนเบิกอย่างเดียวกันสต็อกติดลบได้ แต่ไม่รับประกันว่า Customer ที่อนุมัติราคาแล้วจะมีอะไหล่รองรับ เราจึงจองอะไหล่ตอนเกิด Approval เบิกได้เฉพาะยอดจองของ Work Order นั้น และให้ส่วนที่ขาดเข้าคิว Part Request แบบก่อนหลัง การย้ายยอดใช้ conditional update ใน transaction เดียวกับการเขียน Stock Movement โดยแต่ละสถานะมี `CHECK >= 0`

## Considered Options

- **Pessimistic lock หรือ optimistic lock:** ใช้งานได้ แต่ถือ lock นานกว่าหรือต้อง retry โดยไม่จำเป็น เพราะ conditional update ให้ Postgres ตัดสินได้ในคำสั่งเดียว
- **ยอมให้สต็อกติดลบ:** Syncro และ RepairDesk ทำแบบนี้ แต่ขัดกับเป้าหมายของระบบที่ต้องให้ยอดตรงกับของจริง
- **Serial/lot และหลายคลัง:** ละเอียดกว่า แต่เกินขอบเขต ใช้ 5 สถานะยอดและ 12 ชนิด Stock Movement แทน

ไม่พบเอกสารของระบบที่ศึกษาซึ่งกำหนดกติกาการแย่งอะไหล่ กติกาคิวจึงเป็นการตัดสินใจของโปรเจกต์นี้ ดู [ผลการค้นคว้า](../research/inventory-and-free-hosting.md)
